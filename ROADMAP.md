# DSH Codex Bridge — план следующих изменений

Этот файл хранит решения, найденные во время реальных сквозных проверок плагина.
Пункты не считаются готовыми, пока не реализованы, не проверены тестами и не
опубликованы в новой версии npm.

Статус: пункты этого этапа реализованы в исходниках версии 0.2.0 и покрыты
локальными и runtime-тестами. До завершения выпуска остаются установка пакета из
npm в живой профиль Desktop и пользовательская сквозная проверка панели.

## Основной рабочий процесс

Рекомендуемый маршрут:

1. Пользователь описывает идею.
2. Codex предлагает архитектуру и структуру проекта.
3. DeepSeek самостоятельно реализует проект.
4. Codex проверяет готовый код.
5. DeepSeek исправляет замечания и запускает проверки.

`scaffold` не должен предлагаться как обязательный следующий шаг после `plan`:
он поручает Codex генерировать содержимое файлов и не соответствует основному
маршруту. Основное действие после плана — передача выбранной архитектуры DeepSeek.

## Команды без обязательных промптов

### Review

- `/codex review` — самостоятельно проверить все Git-изменения и связанные
  модули, без дополнительного текста пользователя.
- При отсутствии Git та же команда должна безопасно проверить весь доступный
  исходный код проекта в пределах лимита снимка. Зависимости, сборка, временные
  файлы и секреты исключаются.
- `/codex review focus <текст>` — необязательный дополнительный фокус проверки.
- `/codex review files <путь>|<путь>` — явное ограничение набора файлов.
- Произвольный текст после `review` нельзя молча принимать за путь к файлу.

### Handoff

- `/codex handoff <id>` — передать завершённый отчёт DeepSeek со стандартной
  задачей: исправить все замечания, добавить необходимые тесты, запустить тесты
  и сборку; Codex повторно не запускать.
- `/codex handoff <id> <текст>` — передать тот же отчёт и добавить пользовательское
  уточнение.
- Текст после ID должен быть необязательным.
- Отчёт со статусом `incomplete`, но с конкретными `findings`, разрешено передавать
  DeepSeek. Статус и ограничения проверки должны быть включены в передачу.
- Блокировать handoff следует только когда результата нет или в нём нет данных,
  пригодных для следующего действия. Сообщение об ошибке должно различать
  отсутствующий результат, пустой отчёт и отсутствие задачи.

### Fix

- `/codex fix <id ревью>` — по умолчанию поручить Codex исправить все найденные
  замечания; дополнительный текст не обязателен.
- `/codex fix <id ревью> <уточнение>` — исправить замечания с дополнительным
  требованием пользователя.
- Разрешить `fix` для review со статусом `incomplete`, если отчёт содержит
  конкретные `findings`. Передать Codex ограничения исходного ревью вместе с
  замечаниями, чтобы он не заявлял о полной проверке.
- Не требовать предварительного `handoff` в DeepSeek перед `fix`: пользователь
  должен сразу выбирать, кто исправляет замечания — DeepSeek или Codex.
- Codex только подготавливает предложение изменений. Перед записью интерфейс
  показывает diff и требует отдельного явного подтверждения; затем доступны
  тестирование, повторное ревью и восстановление контрольной точки.
- Блокировать `fix` только при отсутствии результата, отсутствии `findings` или
  когда снимок нужных файлов недоступен. Сообщение должно называть конкретную
  причину блокировки.

## Интерфейс Harness

Основным способом управления должна стать вкладка **Codex Bridge**. Пользователь
не должен помнить ID заданий, коды подтверждения, синтаксис команд или повторять
типовые промпты. Slash-команды сохраняются как дополнительный способ управления,
для автоматизации и диагностики.

Добавить кнопки и поля для основных операций:

- режимы DeepSeek, Codex и «Codex → DeepSeek»;
- получение каталога моделей и выбор модели отдельно для архитектуры, ревью и
  исправлений;
- поле идеи с кнопкой «Построить план» и выбор предложенного варианта;
- «Передать план DeepSeek и реализовать» без обязательного дополнительного
  промпта;
- «Проверить проект» с автоматической областью проверки и необязательными полями
  «Фокус» и «Файлы»;
- выбор действия после ревью: «Исправить в DeepSeek» или «Подготовить исправление
  в Codex»;
- «Исправить все замечания в DeepSeek» без ручного ввода инструкции;
- просмотр diff предложения Codex и отдельное подтверждение его применения;
- повтор, отмена, применение предложения и восстановление контрольной точки;
- список заданий, результаты, ошибки, лимиты и состояние входа Codex CLI;
- предупреждение о недоступной модели с ручным выбором другой модели.

Кнопки должны вызывать те же внутренние операции, что и slash-команды. Выбор
другой модели, применение файлов и передача между моделями остаются явными
действиями пользователя.

Интерфейс должен показывать понятный текущий этап: «идея», «план готов»,
«DeepSeek реализует», «готово к ревью», «найдены замечания», «исправляется» и
«проверка завершена». Для каждого этапа отображается одно основное следующее
действие. Технические ID и точные команды доступны в раскрываемых деталях.

## Критерии следующего выпуска

- Основной сценарий выполняется короткими командами без копирования шаблонных
  промптов и списков файлов.
- Проект без Git можно проверить одной командой `/codex review`.
- `/codex handoff <id>` работает без дополнительного текста.
- Findings из ограниченного (`incomplete`) review можно передать DeepSeek без
  копирования отчёта вручную.
- `/codex fix <id>` исправляет все findings без обязательного текста и работает
  с содержательным `incomplete` review; предварительный handoff не требуется.
- Полный основной маршрут доступен из вкладки **Codex Bridge** без ручного ввода
  slash-команд, ID заданий и шаблонных инструкций.
- Справка и ответы после `plan` ведут к реализации силами DeepSeek.
- Для нового синтаксиса есть модульные и сквозные тесты.
- Поведение проверено на официальном DeepSeek Harness Desktop 0.2.0-rc.2 под
  Windows перед публикацией npm.
