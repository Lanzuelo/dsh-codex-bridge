# DSH Codex Architect

[English](README.en.md) · [Публикация](PUBLISHING.md) · [История изменений](CHANGELOG.md)

Плагин для **официального DeepSeek Harness Desktop 0.2.0-rc.2 на Windows**. Codex проектирует архитектуру и проверяет изменения, DeepSeek выполняет основную разработку. Версия плагина: **0.2.0, предварительный выпуск**. Имя пакета npm: **dsh-codex-architect**.

В одном окне Harness доступны команда `/codex` и вкладка **Codex Bridge** в правой панели. Плагин использует установленный Codex CLI с входом через ChatGPT. OpenAI API-ключ не требуется; перехода на платный API и автоматической замены модели нет.

Версии **0.1.0 и 0.1.1** содержали ошибку активации bundle. Версия **0.1.3** исправила ошибку Windows `EBUSY` после `/codex models`. Версия **0.2.0** добавляет основной интерфейс управления и короткий рабочий маршрут. Обновите пакет и перезапустите Harness.

## Установка

1. Проверьте, что установлены Harness **0.2.0-rc.2**, Git и Codex CLI; в Codex выполнен вход через ChatGPT. Подтверждённая версия CLI: **0.162.0-alpha.17.2**. Для этой alpha-версии интерфейс может измениться после обновления.
2. В Harness откройте **Plugins / Плагины**, выберите добавление пакета и укажите **`dsh-codex-architect`** (npm latest: **0.2.0**). Для точной версии: `dsh-codex-architect@0.2.0`. GitHub-источник: `github:Lanzuelo/dsh-codex-bridge#v0.2.0`. Альтернатива — скачать `.tgz` из [GitHub Releases](https://github.com/Lanzuelo/dsh-codex-bridge/releases) и указать полный абсолютный путь к нему. **Имя `dsh-codex-bridge` в npm принадлежит другому проекту: не устанавливайте его как этот плагин.**
3. Дождитесь успешной активации и перезапустите Harness, если менеджер этого попросит.
4. В чате проекта введите `/codex help`. В правой панели через `+` / страницу выбора вкладок откройте **Codex Bridge**.
5. Нажмите **Загрузить модели**, выберите модель и сохраните её. Можно выбрать одну модель для всех ролей, отдельную для каждой роли или ввести ID вручную. `default` означает штатный default Codex с изолированной конфигурацией запуска.

Если Desktop не видит CLI в PATH, плагин ищет `codex.exe` в `%USERPROFILE%\AppData\Local\OpenAI\Codex\bin\<версия>`. При нестандартной установке укажите `codexPath` в конфигурации строки плагина. Относительный исполняемый скрипт `.cmd` не запускается через shell; предпочтителен абсолютный путь к `codex.exe`.

Пример конфигурации строки плагина в пользовательском patch профиля, **если строка уже существует, измените её, а не добавляйте дубликат**:

```yaml
- id: codex-bridge
  name: dsh-codex-architect
  config:
    codexPath: 'C:\Users\USERNAME\AppData\Local\OpenAI\Codex\bin\VERSION\codex.exe'
    # Необязательно: отдельное локальное хранилище вне каталога проекта.
    stateDirectory: 'C:\Users\USERNAME\.dsh-codex-bridge'
    timeoutMs: 600000
    maxAttempts: 3
```

Установка в рабочий профиль пользователя в рамках разработки не выполнялась. Сначала рекомендуется проверить пакет в отдельном профиле. Обновление Harness требует повторной проверки совместимости; не обходите ограничение версии.

## Основной маршрут в интерфейсе

Откройте вкладку **Codex Bridge** и выберите режим:

- **DeepSeek** — передать идею или исправления DeepSeek без запуска Codex;
- **Codex** — поручить Codex план, предложение файлов или исправление;
- **Codex → DeepSeek** — Codex проектирует и проверяет, DeepSeek реализует и
  исправляет.

Панель показывает текущий этап, последние задания и одноимённые действия:
**Построить план**, **Проверить проект**, **Исправить в DeepSeek**,
**Подготовить в Codex**, **Показать предложение**, **Применить**,
**Восстановить**, **Повторить** и **Остановить**. ID и slash-команды находятся
в технических деталях.

## Новый проект через команды

```text
/codex plan Создай Telegram-бота с PostgreSQL
/codex handoff <id плана>
```

`plan` предлагает до трёх вариантов без записи файлов. `handoff` без дополнительного текста передаёт рекомендуемый вариант DeepSeek для реализации. В режиме Codex панель позволяет выбрать вариант и подготовить содержимое файлов; только отдельное подтверждение `apply` записывает предложение.

В скелете обязательны `docs/architecture.md` и `docs/deepseek-handoff.md`. Существующий `AGENTS.md` может войти в контекст как соглашения проекта; плагин **не создаёт и не перезаписывает** `AGENTS.md`, чтобы не конфликтовать с пользовательскими инструкциями. Для существующего проекта используется тот же `plan`; изменения исходного стека требуют явного запроса.

## Ревью и исправления

```text
/codex review
/codex review focus Проверь особенно обработку повреждённых данных
/codex review files src/auth.ts|src/auth.test.ts --focus валидация
/codex handoff <id ревью>
/codex fix <id ревью>
```

Без путей ревью охватывает staged и unstaged изменения относительно HEAD, удаления и untracked файлы. Без Git плагин проверяет ограниченный безопасный снимок всего проекта и отмечает отсутствие baseline как ограничение. Также передаются основные manifests, архитектурные документы и до 12 локальных зависимостей JS/TS. Если Git-репозиторий находится выше рабочего каталога, выберите его корень. Путь с пробелами допустим; разделитель нескольких путей — `|`.

Ревью возвращает severity, file, line/end_line, evidence, explanation, proposed_fix, confidence, summary и handoff. Тесты и сборка при этом не запускаются. Отчёт относится к сохранённому снимку кода, а не к будущим изменениям. Исключения и ограничения контекста доступны через `show`.

Пользователь сразу выбирает исполнителя. Обе команды принимают содержательный `incomplete`-отчёт с конкретными findings и не требуют шаблонного текста:

```text
/codex handoff <id ревью>
/codex fix <id ревью>
/codex show <id предложения исправлений>
/codex apply <id предложения исправлений> <код подтверждения>
```

`handoff` передаёт замечания DeepSeek со стандартной задачей исправить их и выполнить проверки. `fix` просит Codex подготовить изменения без записи. Дополнительный текст после ID остаётся необязательным уточнением.

## Модели, квоты и отмена

```text
/codex models
/codex model all gpt-5.6-sol
/codex model architect default
/codex model review <поддерживаемый ID>
/codex model fix <поддерживаемый ID>
/codex status
/codex cancel
/codex retry <id задания>
```

Каталог получается только по запросу через документированный `model/list` app-server; сами задания выполняются через `exec`. Каталог не зашит в код. ID `gpt-5.6-sol` вернулся локальным каталогом и прошёл один минимальный запрос во время разработки; это не обещание его будущей доступности.

Если модель недоступна, плагин предупреждает и оставляет выбранный ID; пользователь выбирает другую модель и запускает `retry`. При квоте сохраняется снимок задания, новые запросы блокируются, автоматических повторов и API fallback нет. `retry` — явное решение повторить, со свежим снимком и текущей моделью роли; по умолчанию максимум три попытки одного задания.

DeepSeek не запускается плагином автоматически. `handoff` — явное решение передать результат и продолжить работу, в том числе после квоты Codex. Обычные сообщения и другие плагины Harness находятся вне управления Bridge. Отмена останавливает принадлежащий плагину процесс; таймаут по умолчанию — десять минут.

## Контрольные точки и ограничения

Перед записью сохраняются оригинальные байты всех заменяемых файлов и журнал операции. Изменённые пользователем после снимка файлы не перезаписываются. Откат выполняется явно:

```text
/codex restore <id предложения> <код подтверждения>
```

Откат откажется затирать поздние правки. После сбоя в процессе применения используйте тот же `restore`; оригиналы остаются в `checkpoint-<id>.json`. Не удаляйте это хранилище до завершения восстановления. Откат удаляет только новые файлы предложения и пустые каталоги, созданные этой операцией. Это локальная файловая контрольная точка, без git commit/reset и без изменения Git index.

- Все запросы Codex выполняются с `read-only`, без пользовательского config, с отключённым web search и shell-функциями, из временного каталога вне проекта. Входные исходники передаются ограниченным снимком; исходный каталог не используется как cwd процесса. Изоляция чтения не равнозначна ОС-запрету читать любой файл пользователя.
- Передаются только OS/runtime/proxy переменные окружения и `CODEX_HOME`; произвольные ключи провайдеров из окружения Harness не наследуются.
- Исключаются `.env*` кроме `.env.example`, ключевые файлы, credentials, `.git`, `.aws`, `.ssh`, зависимости и сборки. Это фильтр имён, не универсальный сканер любых секретов внутри исходников.
- Запись ограничена относительными текстовыми файлами; traversal, junction/symlink, Windows reserved names/streams, конфликтующие пути и изменение `AGENTS.md` запрещены. Удаление файлов, двоичные изменения и установка зависимостей не поддерживаются.
- Бюджет снимка: до 60 файлов, 180 КБ исходного текста/diff, дерево до 2000 записей; крупные изменения нужно разбивать. Плагин не отправляет всю историю чата.
- Авто-ревью выключено: переход агента в idle не принят за надёжный сигнал успешного завершения пользовательской задачи. Ручной запуск доступен всегда, когда DeepSeek свободен.
- Вкладка протестирована в браузерном стенде с React установленного Harness; загрузка Host проверена на реальных Cordis/CommandRuntime. Полная проверка установки и работы внутри Desktop ещё требуется.
- Используйте одно активное приложение Harness с этим хранилищем. Хранилище рассчитано на один Host-процесс; межпроцессной синхронизации в 0.1.0 нет.

Состояние, отчёты, снимки и контрольные точки сохраняются локально в `~/.dsh-codex-bridge` или `stateDirectory`. Они могут содержать исходники проекта. Raw OAuth-токены не читаются и не передаются в Harness. Снижение расхода квоты достигается ручным запуском и коротким контекстом; фиксированный процент экономии не обещается.

## Для разработки

Node 24+, Git; production-зависимостей для ядра нет. Host использует peer-пакеты установленного Harness, React и RPC панели предоставляет Desktop.

```powershell
node scripts/check.mjs
node --test test/*.test.mjs
npm.cmd pack --ignore-scripts --pack-destination artifacts
```

Для полного теста junction нужны права на его создание. `scripts/inspect-runtime.mjs <полный путь app.asar>` копирует выбранные файлы установленного runtime в игнорируемый `.compat`, не меняя установку. `scripts/runtime-smoke.mjs` проверяет загрузку с реальными пакетами через `--import ./scripts/runtime-loader.mjs`. `scripts/diagnose.mjs <codex.exe>` проверяет вход и каталог без inference; `scripts/inference-smoke.mjs <codex.exe> <model>` выполняет один модельный запрос и расходует квоту.
