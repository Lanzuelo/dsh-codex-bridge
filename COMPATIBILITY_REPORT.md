## Интеграция

По установленному runtime проверены ctx.commands.register, invocation.agent.session.header.cwd, agent.status, agent.followup, createUserMessage, регистрация правой панели и Commands RPC.

Реализованы slash-команда /codex и вкладка Codex Bridge. Команды и отчёты не входят в контекст DeepSeek автоматически. React и RPC предоставляет Harness; внешнего HTTP-сервиса установленному плагину не требуется.

Задачи выполняются через exec. App-server используется только для явно запрошенного каталога. Все запросы read-only; скелет и исправления возвращаются как предложения. Файлы записывает плагин после подтверждения ID и кода точного содержимого.

Менеджер Desktop описан в [официальном README](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/desktop/README.md). API проверялись по установленной сборке. Её parseInstallSpec поддерживает абсолютный путь к tarball.

Каталог и ChatGPT-авторизация сверены с [официальной документацией Codex](https://learn.chatgpt.com/docs/app-server) и проверены установленным бинарником. Каталог не заменяет фактическую проверку доступа.

## Проверки

- 20 автотестов: Windows paths, traversal, junction, секретные имена, конфликтующие пути, устаревшее предложение, точный откат, поздние правки, Git staged/unstaged/deleted/untracked, полный снимок без Git, focus/files, выбранный diff и локальные зависимости, отмена процесса, plan/handoff, incomplete review → DeepSeek/Codex fix, защита пустого handoff/fix, dashboard, scaffold schema, квоты, недоступная модель и RPC панели.
- Smoke на реальных Cordis и CommandRuntime из app.asar: регистрация, discovery, исполнение, command/run и command/done, отсутствие модельных сообщений, выгрузка.
- Браузерный стенд с React установленного Harness: визуально проверены панель, каталог, выбор модели, сохранение и проектирование. На стенде RPC тестовый; production runner проверен отдельно.
- Один реальный запрос gpt-5.6-sol: тестовая sum, status=complete, findings=0. Пользовательские проекты не передавались.

В ограниченной среде app-server сначала завершался до каталога, а создание junction запрещалось. Запуск этих диагностик вне изоляции подтвердил каталог и junction-защиту. Это отличие среды тестирования, а не доказанная неисправность Desktop.

## Ограничения

1. Выпуск привязан к официальному Desktop 0.2.0-rc.2. Другие сборки требуют повторной проверки.
2. UI 0.2.0 проверен в интерактивном браузерном стенде, а упакованный tarball — через реальные Cordis/CommandRuntime. Обновление рабочего Desktop-профиля до 0.2.0 ещё не проверено.
3. Авто-ревью выключено: idle не считается сигналом успешного завершения пользовательской задачи. Используется ручная кнопка/команда, что допускает ТЗ.
4. DeepSeek запускается только явным handoff. Обычные сообщения и другие плагины вне управления Bridge.
5. Нет установки зависимостей, запуска сборки/тестов проектов, удаления или двоичных правок. Архитектор предлагает скелет и команды дальнейшего выполнения.
6. AGENTS.md не создаётся и не перезаписывается; существующие инструкции сохраняются.
7. Контекст ограничен снимком и бюджетом. Фильтр секретных имён не обнаруживает любые секреты внутри исходников.
8. Read-only ограничивает запись; это не ОС-запрет чтения любых файлов пользователя. Проект не используется как cwd, user config не загружается, shell-функции и web search отключены.
9. Хранилище рассчитано на один активный Host; межпроцессной синхронизации нет.
10. DeepSeek API, баланс и количественная экономия квоты не проверялись.

Итог: подготовлен предварительный пакет с проверенным ядром и протоколом. Статус «проверено внутри Desktop» до установки в отдельный профиль не заявляется.
